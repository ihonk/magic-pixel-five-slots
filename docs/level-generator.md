# 关卡工坊

[打开在线工坊](https://ihonk.github.io/magic-pixel-five-slots/generator.html)；本地开发时，通过静态 HTTP 服务器访问 `generator.html`。工坊使用 Web Worker，不能从 `file://` 页面直接生成。页面打开后会按默认设置自动生成第一关。

## 生成与试玩

1. 选择整体难度（轻松、标准、挑战）和局内节奏（先易后难、先难后易、难易穿插、平稳推进）。节奏沿已消除像素进度分为六段。
2. 选择 0–4 对绑定法师并填写种子。相同参数与种子会复现同一批候选。
3. 点击“生成并验证关卡”。工坊比较 12 个候选，仅从自动通关且满足所选节奏趋势的候选中选择与目标压力曲线偏差最小的一关。若没有候选同时满足两项条件，会提示更换种子或调整绑定对数，不输出未经验证的关卡。
4. 查看 36 × 36 地图、三列法师队列、绑定关系、验证记录和曲线。可直接试玩、复制试玩链接，或导出 JSON。

试玩链接将经过校验的关卡编码在 `index.html#level=…` 中，不依赖浏览器本地存储。游戏首页也可选择“导入关卡”加载 JSON；离线单文件版本可以导入已有 JSON，但工坊生成仍需 HTTP 服务。

当前生成器按六段分层像素结构构造地图，不提供从图片生成地图的功能。

## “自动通关已验证”的含义

验证器在 Worker 中加载正式 `game.js` 与仓库自带的 Three.js 数学、几何逻辑，使用不绘制画面的渲染器替身，以 60 Hz 推进游戏时间，最多模拟 360 秒。它用启发式策略依据当前队首、绑定关系和空位规则执行登带操作，不使用复活。只有棋盘实际清空的候选才标记为通过，并保留一条可重放的点击记录。试玩者选择不同顺序或时机，过程可能不同；通过表示存在这条已验证路径，不表示任何操作都能通关。未找到路径不等于关卡无解。

目标曲线是生成倾向。页面的“压力估计”来自自动通关过程，按队首受阻 30%、传送带占位 15%、可见颜色的可达窄度 10%、零弹药成员等待 10%、当前前沿六行的局部遮挡深度 35% 计算。按消除进度分成六段，每段取该段样本的第 75 百分位数。没有样本的段使用所有样本的平均值。这是规则指标，不是玩家实测难度；局部变化仍可能偏离目标曲线。

节奏趋势另有硬性门槛：先易后难要求后两段平均压力至少比前两段高 3 点；先难后易反之；难易穿插要求第 1、3、5 段平均压力至少比第 2、4、6 段高 3 点；平稳推进要求六段最大值与最小值相差不超过 40 点。难易穿插从高压力段开始。门槛只约束整体趋势，不保证每一段都严格递增、递减或交替。

## JSON 格式

导出的文件包含 `version: 1`、`name`、36 行每行 36 字符的 `map`、三列显式 `lanes`、`links`，以及生成参数、统计和验证记录。地图字符为 `.`、`R`、`B`、`G`、`Y`、`P`；每个法师写成 `{ "color": "R", "charges": 1 }`。绑定对以不同列的两个 `[列索引, 队列行索引]` 标识，其中列索引为 0–2，行索引从队首的 0 开始。

```json
{
  "version": 1,
  "name": "示例关卡",
  "map": ["36 个字符的地图行，共 36 行"],
  "lanes": [[{"color":"R","charges":1}], [], [{"color":"B","charges":2}]],
  "links": [{"id":"A","members":[[0,0],[2,0]]}]
}
```

上方 `map` 是结构示意，不能直接导入。导入时以 `level-core.js` 校验并规范化关卡，最多读取 200 KB。每列最多 48 名、总计最多 96 名法师，每人弹药为 1–3；绑定编号须唯一，且每名法师最多参加一对。显式队列按 JSON 中的顺序出列，不重新排序。`generation`、`stats` 和 `verification` 供工坊展示，不作为游戏运行关卡的必需字段。
