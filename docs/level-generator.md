# 关卡工坊

[打开在线工坊](https://ihonk.github.io/magic-pixel-five-slots/generator.html)；本地开发时，通过静态 HTTP 服务器访问 `generator.html`。工坊使用 Web Worker，不能从 `file://` 页面直接生成。页面打开后会按默认设置自动生成第一关。

## 生成与试玩

1. 选择整体难度（轻松、标准、挑战）和局内节奏（先易后难、先难后易、难易穿插、平稳推进）。节奏沿已消除像素进度分为六段。
2. 选择 0–4 对绑定法师、0–4 块[颜色数字锁区](color-locks.md)、每锁 1–3 次命中、随机或指定开锁颜色，并填写种子。网页默认使用一对绑定法师和一块需要两次命中的锁区。相同参数与种子会复现同一批候选。
3. 点击“生成并验证关卡”。无锁时比较 12 个候选，每增加一块锁再增加 12 个，最多 48 个。工坊仅从自动通关且满足所选节奏趋势的候选中选择与目标压力曲线偏差最小的一关。若没有候选同时满足两项条件，会提示更换种子或调整设置，不输出未经验证的关卡。
4. 查看 36 × 36 地图、锁区、三列法师队列、绑定关系、验证记录和曲线。可直接试玩、复制试玩链接，或导出 JSON。

试玩链接将经过校验的关卡编码在 `index.html#level=…` 中，不依赖浏览器本地存储。游戏首页也可选择“导入关卡”加载 JSON；离线单文件版本可以导入已有 JSON，但工坊生成仍需 HTTP 服务。

生成器按颜色汇总后续所需射击，在不超过五次的前提下均衡分配给较少的法师，通常以四至五次为主；颜色需求少或需要较多绑定对时仍可能出现一至三次。旧版一至三次弹药关卡仍可导入。

当前生成器按六段分层像素结构构造地图，锁区生成为 4 × 3 格的矩形，并自动安排开锁所需弹药和法师。锁区可能把原本相连的同色像素分成数块；生成器按锁区外和每块锁区内各自的初始同色连通区数量，再加上开锁命中次数，保守补足每种颜色的弹药。此预算避免因消除顺序改变而缺少对应颜色的弹药，但队列、绑定或节奏仍可能使某组候选无法通过验证。

## “自动通关已验证”的含义

验证器在 Worker 中加载正式 `game.js` 与仓库自带的 Three.js 数学、几何逻辑，使用不绘制画面的渲染器替身，以 60 Hz 推进游戏时间，最多模拟 360 秒。它用启发式策略依据当前队首、绑定关系、空位和锁区规则执行登带操作，不使用复活。只有像素全部清空、锁区全部解开时，候选才标记为通过，并保留一条可重放的点击记录。试玩者选择不同顺序或时机，过程可能不同；通过表示存在这条已验证路径，不表示任何操作都能通关。未找到路径不等于关卡无解。

目标曲线是生成倾向。页面的“压力估计”来自自动通关过程，按队首受阻 30%、传送带占位 15%、可见颜色的可达窄度 10%、零弹药成员等待 10%、当前前沿六行的局部遮挡深度 35% 计算。按消除进度分成六段，每段取该段样本的第 75 百分位数。没有样本的段使用所有样本的平均值。这是规则指标，不是玩家实测难度；局部变化仍可能偏离目标曲线。

节奏趋势另有硬性门槛：先易后难要求后两段平均压力至少比前两段高 3 点；先难后易反之；难易穿插要求第 1、3、5 段平均压力至少比第 2、4、6 段高 3 点；平稳推进要求六段最大值与最小值相差不超过 40 点。难易穿插从高压力段开始。门槛只约束整体趋势，不保证每一段都严格递增、递减或交替。

## JSON 格式

导出的文件包含 `version: 1`、`name`、36 行每行 36 字符的 `map`、三列显式 `lanes`、`links`、`locks`，以及生成参数、统计和验证记录。旧版关卡可省略 `locks`，导入时视为空数组。地图字符为 `.`、`R`、`B`、`G`、`Y`、`P`；每个法师写成 `{ "color": "R", "charges": 1 }`。绑定对以不同列的两个 `[列索引, 队列行索引]` 标识，其中列索引为 0–2，行索引从队首的 0 开始。

```json
{
  "version": 1,
  "name": "示例关卡",
  "map": ["36 个字符的地图行，共 36 行"],
  "lanes": [[{"color":"R","charges":1}], [], [{"color":"B","charges":2}]],
  "links": [{"id":"A","members":[[0,0],[2,0]]}],
  "locks": [{"id":"L1","x":16,"y":18,"width":4,"height":3,"color":"Y","hits":2}]
}
```

上方 `map` 是结构示意，不能直接导入。导入时以 `level-core.js` 校验并规范化关卡，最多读取 200 KB。每列最多 48 名、总计最多 96 名法师，每人弹药为 1–5；绑定编号须唯一，且每名法师最多参加一对。最多四块锁区，坐标为棋盘内整数，宽高各 1–6 格，锁区不可重叠且每块至少覆盖一个像素；锁编号为唯一的 1–6 位大写字母或数字，开锁颜色为 `R/B/G/Y/P`，命中次数为 1–3。导入校验要求对应颜色弹药至少覆盖原地图连通区和开锁次数，这是基本数量检查，并不证明手写关卡可解。显式队列按 JSON 中的顺序出列，不重新排序。`generation`、`stats` 和 `verification` 供工坊展示，不作为游戏运行关卡的必需字段。
