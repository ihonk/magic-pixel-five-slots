# 跨列双法师连线机制

状态：需求整理，尚未实现。日期：2026-11-27。

本文记录新增机制的规则和验收场景。现有游戏仍使用独立法师；本次只新增文档。

## 1. 机制定义

在地面队列中，为不同列的两名法师添加连线，组成一个绑定对。绑定对需要共同满足出列条件，共同登上传送带，并在双方弹药全部耗尽后共同离场。

以下用“弹药”表示法师剩余施法次数。两人各自保留颜色、弹药数量和施法判断。

本机制首先覆盖跨左右两列的一对法师。现有工程有三列队伍；示例中的两列不意味着把整个游戏改成两列。

## 2. 已确认的规则

### 地面队列：两人都到队首才可出列

- 每列仍然只能操作队首法师，不能跳过前方成员。
- 任一绑定成员处于队首，但另一成员还在本列后方时，不能单独出列。
- 两名绑定成员必须同时成为各自列的队首，才能申请成对登带。
- 点击满足条件的绑定成员，应执行整对登带；不能先送走其中一人。

示例中的队列从上到下、从前到后排列：

| 阶段 | 左列 | 右列 | 操作结果 |
| --- | --- | --- | --- |
| 初始 | **1**、2、3、4 | **a**、b、c、d | 1 与 b 绑定。点击 1 无法出列，因为 b 前方还有 a。 |
| a 出列后 | **1**、2、3、4 | **b**、c、d | 1 和 b 都成为队首，满足队列条件。 |
| 绑定对登带后 | **2**、3、4 | **c**、d | 1 与 b 一起出列，两列分别补位。 |

表中加粗的是当前队首。a 的登带仍需满足其自身条件；如果 a 也是绑定成员，则需先解决 a 所属绑定对的条件。

### 传送带：需要两个相邻空位

- 绑定对占用两个法师位置，五人容量的传送带上至少要有两个空位。
- 只有零个或一个空位时，两人都留在地面，不能只上一人。
- 两个空位已经相邻时，两名法师同时登上这两个位置。
- 总空位不少于两个，但空位分散时，传送带必须自动调整在带法师的位置，形成两个相邻空位，再让绑定对同时登带。
- 自动调整只改变位置，不能销毁在带法师、扣除弹药或把他们当作已离场。

示意（`□` 为空位，`A/B/C` 是已在带上的法师）：

```text
原位置：    [A][□][B][□][C]
自动重排：  [A][B][□][□][C]
成对登带：  [A][B][1][b][C]
```

这是说明“挪出连续空位”的一种排布示例，不限定具体挪动路径。重排不应只是等待传送带转动：整体循环移动不会改变两个空位之间是否相邻。

### 施法与离场：各自射击，共同退出

- 登带后两名法师继续随传送带循环移动，各自检查正上方列底部暴露的像素颜色。
- 只有当前位置满足现有施法条件的成员才发射竖直光线，消耗该成员自己的弹药，按现有四方向同色连通规则消除。
- 两人不要求同时开火，弹药也不共享。
- 任意一人的弹药先耗尽时，该成员留在带上等待伙伴，继续占用一个位置，不再射击。
- 只有两名成员的弹药都为零时，绑定对才同时离场，一起释放两个位置。

例如，1 已耗尽弹药、b 还剩一发时，1 不能先消失。b 仍需移动到可消除的位置并完成最后一发，之后两人一起离场。

## 3. 状态与条件

| 绑定对状态 | 进入条件 | 行为与退出条件 |
| --- | --- | --- |
| 等待双队首 | 至少一人尚未到队首 | 禁止单独登带；先派遣挡在前方的法师。 |
| 等待容量 | 两人均到队首，空位少于两个 | 两人留在地面，等待空位释放。 |
| 等待连续空位 | 两人均到队首，总空位足够但分散 | 自动重排，准备相邻的两个位置。 |
| 成对登带 | 相邻的两个空位已准备好 | 两人作为一次操作共同登带，两列同时补位。 |
| 在带施法 | 两人已登带，尚有成员弹药大于零 | 各自按当前位置和颜色射击。 |
| 单方等待 | 恰有一人弹药为零 | 耗尽者随带等待；另一人继续施法；仍占两位。 |
| 共同离场 | 双方弹药都为零 | 同时离场，释放两位。 |

## 4. 为后续实现提出的处理建议

本节是建议方案，不作为用户已经确认的额外规则。

- **绑定范围**：首版采用一对一绑定，每人最多一个伙伴；不在首版扩展三人或多重连线。
- **登带操作**：两人都到队首后，点击任一成员即可触发整对登带，不需要连点两次，也不因条件刚满足就自动派遣。
- **位置预留**：接受登带操作后，同时预留两个位置，再开始重排和登带动画。动画期间不允许其他点击占走这些位置。
- **重排安全**：重排中的法师暂时停止发射，落稳后再检查当前位置，防止挪动过程中从错误列射击；保留已有法师的前后顺序。
- **在带关系**：建议两人登带后保持相邻，重排其他法师时把已有绑定对作为整体移动。两人横跨循环出口、入口时，也要能辨认其绑定关系。
- **末发动画**：最后一发命中及相关可见消除完成后，再播放两人的共同离场动画；不要在弹药计数归零的那一帧直接删除模型。
- **绑定可视化**：地面展示连线或配对标记；点击受阻成员时同时提示伙伴和前置阻挡。登带后保留配对标记，耗尽者显示“等待伙伴”。
- **失败判断**：零弹药的等待成员仍计入容量；它不能攻击，也不能被当成可立即释放的空位。仍有弹药的伙伴暂无目标时，继续使用现有循环等待和死局判断。
- **复活与重开**：建议复活以整对为单位处理，不能只退回绑定成员之一，剩余弹药均保留。重开应清除预留、重排、绑定等待及相关计时任务。

## 5. 实现前仍需确定的边界

| 问题 | 当前建议 |
| --- | --- |
| 哪些列之间可以绑定？ | 示例为左列与右列；三列工程中是否允许任意两列绑定，后续确定。 |
| 循环首尾的两个空位是否算相邻？ | 逻辑上按环形位置判断相邻；如果入口和出口在画面两端，应确保登带和连线表现能清楚说明两人属于一对。该口径仍待确认。 |
| 带上必须一直相邻，还是只要求登带时相邻？ | 建议始终相邻；用户目前明确要求的是登带时相邻、离场时同步。 |
| 两对法师同时具备登带条件时如何处理？ | 建议按玩家点击顺序逐对受理，先预留者优先，避免重复占位。 |
| 复活原规则退回三人，遇到绑定对怎么办？ | 建议优先保证绑定完整性；具体退回人数和选择顺序需单独确定。 |
| 清空棋盘时，绑定对仍有剩余弹药怎么办？ | 建议维持现有清空即胜利；剩余法师进入通关表现，不为耗尽弹药而继续空转。 |

## 6. 验收场景

以下为后续开发的验收清单，本次文档提交不代表这些功能已经实现或测试通过。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| 01 | 1 在左列队首，伙伴 b 前面还有 a | 点击 1 不出列，不占带上位置；提示先派遣 a。 |
| 02 | a 已出列，1 与 b 同时处于队首 | 满足队列条件，后续检查两个相邻空位。 |
| 03 | 双队首已就绪，但带上仅一个空位 | 两人都留在地面，没有单独登带。 |
| 04 | 双队首已就绪，已有两个相邻空位 | 两人一起登带；两列各自补位；占用数增加二。 |
| 05 | 双队首已就绪，有两个分散空位 | 自动挪位形成相邻空位，再成对登带；原有成员和弹药不丢失。 |
| 06 | 登带重排期间再次点击其他队首 | 已预留的两个位置不会被抢占，也不会出现超容量。 |
| 07 | 1 正上方可消除，b 正上方暂不可消除 | 只有 1 射击，b 不扣弹药。 |
| 08 | 1 弹药为零，b 仍有弹药 | 1 随带等待、停止射击；两人仍占两位。 |
| 09 | b 完成最后一发，双方弹药都为零 | 两人同时离场，释放两位。 |
| 10 | 一方耗尽，另一方等待目标 | 不提前释放耗尽者，不因其零弹药错误判定整对完成。 |
| 11 | 已有绑定对在带上，另一对申请登带 | 如需重排，不拆开已有绑定对；具体持续相邻规则按第 5 节最终口径验收。 |
| 12 | 等待伙伴或重排期间重开 | 关卡复位，无旧连线、占位预留、挪位动画或离场回调残留。 |

## 7. 后续工程改动范围

后续实现需覆盖关卡中的绑定关系、队首联合判断、相邻双位置预留与重排、共同离场、等待状态表现，以及复活和死局判断的适配。现有单法师出列、竖直射击、底部遮挡和四方向连通消除规则继续作为基础。
