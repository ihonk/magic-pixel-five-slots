# 颜色数字锁区

状态：已实现。第四关「色锁试炼」是内置示例；[直接试玩](https://ihonk.github.io/magic-pixel-five-slots/?level=4)。前三关不含锁区。关卡工坊可生成带锁关卡，参数与 JSON 格式见[关卡工坊说明](level-generator.md)。

## 规则

- 锁区覆盖一个矩形区域，包括其中的空白格。锁未解除时，它保护内部像素，并挡住从下方射向该矩形的光线。巫师仍只检查自己正上方的列：该列最下方遇到的普通像素或锁区就是当前目标，不能越过锁区射击后面的像素。
- 每块锁显示指定颜色和剩余命中数字。只有同色法师可击中；每次命中消耗该法师一发弹药，并使数字减一。飞行中的命中会预留次数，避免多发同时命中而使数字低于零。
- 数字降到零时锁区解除，内部像素保持原样。随后须按这些像素自身的颜色正常射击和消除；开锁的颜色不必与内部像素颜色相同。
- 活跃锁区阻断同色像素的四方向连通，也阻断引信式消除向锁内或穿过锁区蔓延。解除后，像素重新参与普通连通和竖直射击。
- 若绑定法师的最后一发用于开锁，绑定对仍遵守双方弹药耗尽、末发可见效果完成后共同离场的规则。通关需要清空所有像素并解除所有锁区。

## 内置示例

第四关先露出红色底板，再露出覆盖蓝色 3 × 3 像素的黄色 `L1` 锁区。红色法师用一发清除底板；黄色法师命中两次解除锁；蓝色法师再用一发清除内部像素。锁区的两发不会顺带消除蓝色像素。

## 关卡数据

在 `version: 1` 的关卡对象中，`locks` 可省略，省略时视为 `[]`。每块锁写成：

```json
{"id":"L1","x":17,"y":21,"width":3,"height":3,"color":"Y","hits":2}
```

`x`、`y` 是矩形左上角在 36 × 36 棋盘上的零起始坐标。每关最多四块锁；宽、高各为 1–6 格，必须位于棋盘内、彼此不重叠，每块至少覆盖一个像素。`id` 为不重复的 1–6 位大写字母或数字；颜色为 `R/B/G/Y/P`；所需命中次数为 1–3。导入时会校验对应颜色法师的总弹药是否足够覆盖开锁次数和地图连通区。

## 回归场景

| 场景 | 预期 |
| --- | --- |
| 锁区下方还有普通像素 | 先命中最下方的普通像素，不能越过它开锁。 |
| 锁区内有空白格 | 整个矩形仍挡住射线和连通消除。 |
| 错色法师经过锁下方 | 不射击、不扣弹药。 |
| 同色多名法师接连发射 | 飞行中的命中预留次数；锁数字不会被多扣。 |
| 最后一次开锁命中 | 锁解除，内部像素仍在，需继续射击。 |
| 同色像素分布在锁内外 | 锁活跃时消除不能跨越锁区；解除后按普通连通规则处理。 |
| 绑定成员用最后一发开锁 | 等可见效果结束后，再按绑定双方弹药状态共同离场。 |
| 关卡不含 `locks` | 与旧版无锁关卡兼容。 |
