# Magic Fever 质量检查

运行针对正式游戏逻辑的确定性检查：

```sh
node qa/test-game.mjs
node qa/integration.mjs
node qa/generator.mjs
node qa/generator-ui.mjs
node qa/locks.mjs
```

测试脚本会提取并执行仓库中的实际玩法函数，不会另行复制算法。涉及 DOM 或 WebGL 的重置行为，则直接检查正式函数实现。覆盖内容如下：

- 四方向连通判断，包括 L 形连通并排除斜向连接；
- 分别判断每一列最底部仍存在的方块；
- 五个槽位占满时的僵局判断；
- 引信沿命中的同色连通区域遍历；
- 循环传送带的间距与回绕、巫师当前位置对应的列，以及竖直发射对齐；
- 五名巫师的传送带容量，以及传送带偏移和纹理重置；
- 三列纵队各自仅允许队首上场、队首离开后解锁下一位，以及重复上场的拦截；
- 复活返回的巫师恢复各自纵队的队首优先级；
- 经典布局下的巫师自由选择；
- 五槽僵局判断和待处理发射的结算保护；
- 继续游戏或复活时保留施法次数和队列顺序；
- 重新开始时清理计时器、投射物、闪光、粒子、提示和过场；
- 关卡切换的定时调度，以及巫师 GPU 资源释放。

此检查不依赖额外软件包，可在 CI 或本地通过 Node.js 运行。

`test-game.mjs` 包含 28 项规则检查。绑定机制重点覆盖双队首、相邻双空位、分散空位重排及预留、零弹药等待与共同离场、整对复活和重开；还枚举五槽传送带所有至少两个空位的布局，并检查跨末首槽的已有绑定对，确保重排不丢失或复制法师，且保留环形顺序。

`integration.mjs` 在 Node VM 中加载仓库自带的 Three r147 和完整 `game.js`，以轻量画布与渲染器替身运行三项集成场景：首关 120 秒自动快进至棋盘清空；阻挡法师出列后绑定对共同登带；重开后清除登带状态并重建绑定。VM 替身不验证真实 WebGL 绘制或手机外观。

`generator.mjs` 测试固定种子、三档难度和四种节奏、0–4 对绑定、36×36 地图与不合法数据拦截；调用真实 `generator-worker.js` 验证 12 个候选，并将选中关卡的操作记录在独立的正式游戏运行环境中回放至通关。它还测试 JSON 文件和 URL hash 导入。共用的 Node VM 环境位于 `runtime.mjs`。

`generator-ui.mjs` 用轻量 DOM 和 Worker 替身实际运行工坊脚本，检查进度、结果按钮、取消与错误路径，并验证导出的 JSON 与试玩链接。生成器规则测试还检查实测节奏门槛：先易后难、先难后易、难易穿插及平稳推进；当 12 个候选均不符合目标节奏时，Worker 返回错误，不输出未经验证的关卡。压力曲线按消除进度六段中的较高压力样本计算。

`locks.mjs` 用正式游戏运行自定义小关卡，检查最近下方遮挡、锁颜色、逐发扣血与命中预留、锁未解时禁止胜利、解锁后仍需清除内部像素、重开复位，以及绑定法师共同离场。规则测试还检查锁区隔断同色连通与引信；生成器测试用真实 Worker 验证带锁关卡的 24 个候选，并独立回放操作直到全部锁与像素清空。生成候选的弹药预算须覆盖锁外和各锁内的同色原子区域，再加开锁击数；包括固定四锁三击样例。集成测试包含默认第四关的锁区挑战。
