# 魔法像素 · 循环传送带实验场

一款面向手机浏览器的 Three.js 益智游戏原型，提供网页版本和可离线直接打开的单文件版本。

在线试玩：https://ihonk.github.io/magic-pixel-five-slots/

甜品图案实验：[甜甜圈三种节奏试玩](experiments/donut/)。同一张 36×36 图案提供平稳、递进、交替三个配置，可离线打开或下载 JSON；均通过正式游戏模拟和独立回放。曲线符合现有整体趋势门槛，并非逐阶段严格拟合或玩家实测难度。

新增机制：[跨列双法师连线](docs/linked-wizards.md)。首关的左列第一位与右列第二位组成绑定对；两人都到队首且传送带有两个空位时，可点击任一成员成对登带。

关卡工坊：[在线生成关卡](https://ihonk.github.io/magic-pixel-five-slots/generator.html) · [生成与验证说明](docs/level-generator.md)。可选难度、局内节奏、绑定对数和种子，预览关卡后导出 JSON 或直接试玩。

新增机制：[颜色数字锁区](docs/color-locks.md)。[试玩第四关「色锁试炼」](https://ihonk.github.io/magic-pixel-five-slots/?level=4)：使用指定颜色的法师击中锁区，将数字降到零后才能消除其中的像素。

## 玩法与表现

- 36 × 36 像素棋盘，共有四个演示关卡；前三关无锁，第四关展示锁区。
- 点击地面的待命巫师，将其送上最多容纳五人的循环传送带。带面由五块深浅相间的色块组成，去掉了方向箭头，每块色块随对应槽位从左向右循环移动。
- 地面三列纵队各自从上往下依次上场，每列只能点击最上方的队首巫师。队首离开后，同列后续巫师向前补位；复活返回地面的巫师排在各自纵队前方。
- 带连线的两名巫师必须同时位于各自队首，并占用两个相邻的传送带位置。若空位分散，传送带会先挪位；两人各自施法，直到双方弹药都耗尽才一起离场。
- 传送带通常以每秒 **72 个设计像素**移动。当所有尚未离场的巫师都已在传送带上落稳，且至少一名巫师还有施法次数、棋盘上也有一列底部露出与其同色的像素时，带速提升至每秒 **200 个设计像素**。条件不再满足时恢复常速。
- 当巫师移动到某一棋盘列正下方，且该列最近的像素或锁区与巫师同色时，巫师才会竖直向上发射；它不会跨列寻找目标。
- 同色像素按上、下、左、右连通；命中后由 shader 呈现沿连通区域推进的引信式消除。锁区阻隔射线与连通消除，解锁后内部像素仍须另行射击。
- 巫师保留有限施法次数。传送带满员或局面受阻时可通过复活机制继续，清空棋盘后进入通关结算与下一关。
- 画面包含倒角像素、巫师队列与过场效果；音效由 Web Audio API 即时合成，不依赖外部音频文件。

当前版本还处理了计时器与视觉残留清理、GPU 资源释放、手机屏幕裁切，以及重开按钮的状态恢复。

## 运行与构建

网页版本由以下文件组成：

- `index.html`：页面结构、界面样式与交互容器
- `game.js`：关卡、玩法、渲染、动画与合成音效
- `level-core.js`：关卡数据校验、生成和压力曲线的共享逻辑
- `vendor/three.r147.min.js`：本地 Three.js r147 运行库

通过静态文件服务器打开 `index.html` 或 `generator.html` 即可运行在线结构。工坊使用 Web Worker 验证候选关卡，需要 HTTP 服务或在线地址，不能通过 `file://` 直接生成。游戏首页可导入工坊生成的 JSON；试玩链接把关卡数据放在 URL 中，无需本地存储。

若需要不依赖服务器的单文件游戏版本，执行：

```sh
python3 tools/build-standalone.py
```

脚本会将页面、关卡校验逻辑、游戏逻辑和本地 Three.js 运行库内联，生成 `magic_fever_standalone.html`；该文件可离线直接打开并导入已有 JSON 关卡。
